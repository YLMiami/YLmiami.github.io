Recipe Agent

An interactive agent that answers cooking questions from a crawled recipe collection

Yunfei Liang

[GitHub: coming]

TL;DR: You type a question. A local language model decides whether to search the collection, read a recipe in full, or compare every recipe by a nutrition value, and it keeps calling tools until it can answer. The collection is about 4,000 dessert recipes in Postgres with pgvector.

3 tools
search, read one recipe, and rank the whole collection by calories, fat, carbs or protein
4,066
recipes, stored as 16,057 typed segments with 384-d embeddings
Local
embeddings, reranker and the chat model all run on a laptop; the database starts with Docker Compose

Design decisions

  • An agent instead of a fixed pipeline. The first version always retrieved one recipe and answered from it. That cannot answer "which recipe has the fewest calories?", which needs the whole collection, and it gets in the way of "how do I fix a sunken cake?", which needs none of it. With tools, the model chooses.
  • Three narrow tools instead of free SQL. The model never writes a query. The ranking tool takes a fixed list of nutrients and a filter, so a bad call can only return an error.
  • Errors go back to the model as data. A wrong id comes back as a message the model can read and correct, and the session keeps running.
  • Search short segments, read the whole recipe. Titles, summaries, ingredient lists and nutrition lines are embedded separately. All are under 1,000 characters, so nothing needs chunking. Search returns ids, and details must come from reading the recipe.
  • A plain loop, no framework. Call the model, run the tools, append the results, stop after six steps. Every step is kept in a trace the prompt can show.

The collection

A preferential crawler ranks its frontier by dessert keywords and respects robots.txt. It discovered 24,530 pages and downloaded 5,136. Extraction kept 4,066 recipe pages and split each into title, summary, ingredients, instructions and nutrition.

Status

  • The loop, the tools and the model client are covered by tests that run without a database or a model.
  • A ten-question evaluation records which tools the agent picks, how many steps it takes and how long. It has not been run on the full collection yet, so there are no numbers here.

The crawler, extraction and database schema come from a 2026 university course project built with two teammates, used with permission. The agent, tools and evaluation are new.
